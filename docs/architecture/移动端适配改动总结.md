# 移动端适配改动总结

## 📋 改动概览

为了支持移动端（React Native）和PC端（Electron）的统一代码库，我们对项目进行了架构优化，将所有平台相关的逻辑集中到 `WebAdapters.js` 适配层。

### 1. WebAdapters.js - 新增模型路径适配器

**文件**: `src/adapters/WebAdapters.js`

**新增内容**: `ModelPathAdapter` 对象（第1274-1444行）

#### 1.2 平台路径映射

| 平台 | 环境 | 模型基础路径 |
|------|------|-------------|
| **Android** | React Native | `file:///android_asset/models` |
| **iOS** | React Native | `${RNFS.MainBundlePath}/models` |
| **PC开发** | Electron + localhost:3000 | `http://localhost:3000/models` |
| **PC生产** | Electron + file:// | `./models` |
| **Web浏览器** | Chrome/Firefox | `./models` |
| **Node.js** | 纯Node环境 | `./public/models` |

#### 1.3 执行提供者映射

| 平台 | 优先级 | 说明 |
|------|--------|------|
| **iOS** | CoreML > CPU | 使用苹果硬件加速 |
| **Android** | NNAPI > CPU | 使用Android神经网络API |
| **Web** | WebGPU > WebGL > WASM > CPU | 浏览器GPU加速 |
| **PC** | CUDA > DirectML > CPU | NVIDIA或DirectX加速 |

#### 改动4: 简化执行提供者检测

```javascript
// 找到 detectAvailableProviders 方法（约第279行）
// 在方法开头添加
async detectAvailableProviders() {
  if (this.cachedProviders) {
    return this.cachedProviders;
  }
  
  try {
    // 🆕 先从适配器获取推荐的提供者列表
    const recommendedProviders = ModelPathAdapter.getExecutionProviders();
    logger.debug(`🔍 适配器推荐的执行提供者: ${recommendedProviders.join(', ')}`);
    
    // 检查ONNX Runtime实际支持的提供者
    const ort = this.ort;
    const availableProviders = [];
    
    if (typeof ort.getAvailableProviders === 'function') {
      const ortProviders = await ort.getAvailableProviders();
      logger.debug(`🔍 ONNX Runtime支持的提供者: ${ortProviders.join(', ')}`);
      
      // 取推荐列表和实际支持的交集
      for (const provider of recommendedProviders) {
        if (ortProviders.includes(provider)) {
          availableProviders.push(provider);
        }
      }
    }
    
    // 如果没有找到可用的提供者，使用CPU
    if (availableProviders.length === 0) {
      availableProviders.push('cpu');
      logger.debug('⚠️ 使用默认 CPU 推理');
    } else {
      logger.debug(`✅ 最终选择的执行提供者: ${availableProviders.join(', ')}`);
    }
    
    // 缓存结果
    this.cachedProviders = availableProviders;
    return availableProviders;
    
  } catch (error) {
    logger.error('❌ 检测执行提供者失败:', error);
    this.cachedProviders = ['cpu'];
    return ['cpu'];
  }
}
```

## 📦 移动端配置步骤

### 1. 安装依赖

```bash
# 安装ONNX Runtime React Native版本
npm install onnxruntime-react-native

# 重新链接原生模块（React Native 0.60+自动链接）
cd android && ./gradlew clean
cd ios && pod install
```

### 2. 复制模型文件

#### Android:
```bash
# 创建assets目录
mkdir -p android/app/src/main/assets/models

# 复制模型文件
cp public/models/*.onnx android/app/src/main/assets/models/
```

#### iOS:
```
1. 打开 ios/ImageClassifierApp.xcworkspace
2. 右键项目 -> Add Files to "ImageClassifierApp"
3. 选择 public/models/ 目录
4. 勾选 "Copy items if needed" 和 "Create folder references"
```

## 🎯 改动优势

### 代码质量提升

| 指标 | 改动前 | 改动后 | 改进 |
|------|--------|--------|------|
| **Service层复杂度** | 需要平台判断 | 完全平台无关 | ✅ 简化 |
| **代码行数** | ~100行平台判断 | 0行平台判断 | ✅ 减少100行 |
| **可维护性** | 分散在多处 | 集中在适配器 | ✅ 提升 |
| **可测试性** | 难以mock | 容易mock | ✅ 提升 |
| **可复用性** | 每个Service重复 | 所有Service共享 | ✅ 提升 |

### 架构优势

```
改动前：
┌─────────────────────────────────────┐
│  ImageClassifierService             │
│  ├─ 平台检测代码 (30行)              │
│  ├─ 模型路径处理 (50行)              │
│  ├─ ONNX Runtime加载 (20行)          │
│  └─ 业务逻辑                         │
└─────────────────────────────────────┘

改动后：
┌─────────────────────────────────────┐
│  ImageClassifierService             │
│  └─ 纯业务逻辑                       │
│     ↓ 调用                           │
│  ModelPathAdapter (WebAdapters)     │
│  ├─ 平台检测                         │
│  ├─ 模型路径处理                     │
│  └─ ONNX Runtime加载                 │
└─────────────────────────────────────┘
```
