# 阿里云App备案信息提取指南

## 📋 概述

本指南帮助您提取阿里云App备案所需的信息：
1. **具体使用的域名** - 应用使用的域名
2. **安卓平台软件包名称** - Android应用的包名
3. **公钥** - 应用签名证书的公钥
4. **证书MD5指纹** - 签名证书的MD5指纹

## 🚀 快速开始

### 方法1: 使用自动化脚本（推荐）

1. **打开PowerShell**
   ```powershell
   cd android
   ```

2. **运行脚本**
   ```powershell
   .\get-aliyun-filing-info.ps1
   ```

3. **按提示输入信息**
   - 输入密钥库密码
   - 输入具体使用的域名（例如: `www.xintuxiangce.top`）

4. **获取结果**
   - 脚本会在控制台显示所有信息
   - 同时保存到 `aliyun-filing-info.txt` 文件

### 方法2: 指定参数运行

如果您的keystore文件路径或别名不同：

```powershell
# 指定keystore路径和别名
.\get-aliyun-filing-info.ps1 -KeystorePath "path/to/your.keystore" -Alias "your-alias"

# 指定域名（跳过询问）
.\get-aliyun-filing-info.ps1 -Domain "www.example.com"
```

## 📝 手动提取方法

如果脚本无法运行，可以手动提取信息：

### 1. 获取应用包名

查看 `app/build.gradle` 文件中的 `applicationId`：

```gradle
defaultConfig {
    applicationId "com.imageclassifier.v2"  // 这就是包名
}
```

### 2. 获取证书MD5指纹

```powershell
keytool -list -v -keystore android-release-key.keystore -alias key0
```

在输出中查找 `MD5:` 行，例如：
```
MD5:  A1:B2:C3:D4:E5:F6:...
```

去掉冒号，转换为大写，得到32位十六进制字符串。

### 3. 获取公钥

```powershell
# 导出证书
keytool -export -rfc -keystore android-release-key.keystore -alias key0 -file cert.pem

# 查看证书内容
cat cert.pem
```

从证书中提取BASE64编码的公钥（去掉 `-----BEGIN CERTIFICATE-----` 和 `-----END CERTIFICATE-----` 标记，去掉换行符）。

## 🔍 常见问题

### Q1: 找不到keytool怎么办？

**解决方案：**
- 安装 Android Studio（自带JDK）
- 或安装JDK并添加到系统PATH
- keytool通常位于：
  - `C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe`
  - `C:\Program Files\Java\jdk-XX\bin\keytool.exe`

### Q2: 不知道密钥别名怎么办？

**解决方案：**
```powershell
# 列出所有别名
keytool -list -keystore android-release-key.keystore
```

### Q3: 忘记密钥库密码怎么办？

**解决方案：**
- 如果使用的是发布密钥，必须找回密码（无法重置）
- 如果是测试密钥，可以重新生成
- 建议使用密码管理器保存密码

### Q4: MD5指纹格式不对？

**确保：**
- 32位十六进制字符（0-9, A-F）
- 全部大写
- 没有冒号分隔符
- 例如：`A1B2C3D4E5F6789012345678901234567890AB`

### Q5: 公钥格式不对？

**确保：**
- 是证书的BASE64编码字符串
- 不包含 `-----BEGIN CERTIFICATE-----` 和 `-----END CERTIFICATE-----`
- 不包含换行符
- 是一串连续的BASE64字符

## ⚠️ 重要提示

1. **密钥安全**
   - 妥善保管keystore文件和密码
   - 不要将keystore文件提交到Git仓库
   - 建议备份到安全位置

2. **信息准确性**
   - 确保域名与应用实际使用的域名一致
   - 确保使用发布签名（不是debug签名）
   - 证书信息必须与实际上架的APK签名一致

3. **备案流程**
   - 先完成域名备案
   - 再提交App备案信息
   - 备案信息需要与实际上架的应用信息一致
